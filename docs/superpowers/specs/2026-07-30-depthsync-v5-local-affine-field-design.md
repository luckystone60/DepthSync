# DepthSync V5：光流引导的局部仿射场

日期：2026-07-30
状态：已确认方向，待书面设计复核

## 1. 背景与问题定义

Live Photo 由一段 3 秒、90 帧的视频和一张与视频中间帧对齐的照片组成。视频深度由轻量、时域稳定的模型产生，照片深度由高质量单帧模型产生。两者在分辨率、尺度、值域和局部结构上存在差异，直接切换会造成虚化跳变。

当前 V4 使用全局单调 LUT 和逐帧全局仿射校正。它能稳定统一整体值域，但存在不可消除的表达上限：当墙面、人物和地面在视频深度中具有相近数值、在照片深度中却需要不同校正时，全局函数无法同时满足这些区域。早期版本通过固定区域或传播照片残差实现局部校正，又因硬边界、错误运动和遮挡区域继承残差而产生墙面分层、轮廓拖影和主体破坏。

V5 改变校正对象：不传播照片深度或照片残差，而是在锚帧估计连续的局部仿射参数场，再利用双向光流把参数沿真实运动轨迹传播。无法可靠对应的区域连续回退到 V4 全局结果。

## 2. 目标与非目标

### 2.1 目标

1. 在局部区域内向照片深度的尺度和值域对齐，而不局限于全局映射。
2. 保持或提升当前 V4 的主体和全图时域稳定性。
3. 遮挡、显露、出界和光流失败区域不出现照片残差拖影。
4. 3 秒、90 帧序列的拍后准备阶段目标耗时为 1–2 秒。
5. 允许准备阶段运行一个小型光流模型并缓存中间结果。
6. 播放阶段不运行神经网络，仅执行 LUT、低分辨率场上采样和逐像素仿射变换。
7. 不依赖人物分割 mask。
8. 保留 V4 为安全回退路径，并输出可直接比较的深度视频。

### 2.2 非目标

1. 本版本不展示或优化最终人像虚化渲染。
2. 不训练新的深度模型或端到端深度修正网络。
3. Python 原型只验证算法上限、稳定性和数据规格，不把桌面端耗时等同于手机端耗时。
4. 首版不以最低存储为第一目标；确认效果后再量化和压缩参数场。

## 3. 总体架构

V5 分为拍后准备和播放两个阶段。

### 3.1 拍后准备阶段

1. 运行 V4 全局对齐，得到每帧基础深度 `B_t`。
2. 在照片锚帧上，以照片深度为监督，拟合低分辨率局部仿射场。
3. 对相邻 RGB 帧计算前向、后向光流和流置信度。
4. 通过前后向一致性判断遮挡、显露、出界和不可靠匹配。
5. 从锚帧向前、向后传播仿射参数，而不是传播照片残差。
6. 在低分辨率网格上执行置信度加权的空间正则和轨迹时域滤波。
7. 将每帧的局部参数场保存到 Live Photo 附属数据中。

### 3.2 播放阶段

1. 对视频深度应用 V4 全局 LUT，得到 `B_t`。
2. 使用当前帧 RGB 和 `B_t` 对低分辨率参数场做联合上采样。
3. 应用局部仿射校正和置信度融合：

   `Y_t(x) = w_t(x) * (a_t(x) * B_t(x) + b_t(x)) + (1 - w_t(x)) * B_t(x)`

4. 对输出做合法值域裁剪，生成同步后深度图。

当 `w_t(x)=0` 时，输出严格等于 V4。该恒等回退是 V5 的核心安全条件。

## 4. 输入、输出与中间数据

### 4.1 输入

| 数据 | 规格 | 说明 |
| --- | --- | --- |
| RGB 视频 | `T × H_rgb × W_rgb × 3`, `uint8` | 当前验证固定取 3 秒、90 帧 |
| 视频深度 | `T × H_v × W_v`, `float16/float32` | Video Depth Anything Small Stream 模拟 |
| 照片深度 | `H_p × W_p`, `float16/float32` | DepthPro 模拟 |
| 锚帧索引 | 标量 `int32` | 对应照片拍摄时刻，通常为中间帧 |
| 可选人脸框 | 归一化坐标 | 只用于评估和保护，不作为硬分割边界 |

所有深度在进入局部拟合前转换为“近大远小”方向一致的归一化视差。照片的有效分位范围映射到 `[0, 1]`，同时保存恢复显示值域所需的全局元数据。

### 4.2 光流数据

光流在缩放后的 RGB 帧上计算，默认工作分辨率为 `256 × 144`：

| 数据 | 规格 |
| --- | --- |
| 前向流 | `(T-1) × 144 × 256 × 2`, `float16` |
| 后向流 | `(T-1) × 144 × 256 × 2`, `float16` |
| 模型置信度或不确定度 | `(T-1) × 144 × 256`, `float16` |
| 前后向一致性置信度 | `(T-1) × 144 × 256`, `float16` |

这些数据只在准备阶段存在，参数场生成后即可释放，不写入最终 Live Photo。

### 4.3 持久化局部参数场

默认网格为 `64 × 36`，每帧保存三个 FP16 通道：

| 通道 | 含义 | 约束 |
| --- | --- | --- |
| `delta_scale` | `a - 1` | 使 `a` 最终限制在 `[0.5, 1.5]` |
| `offset_norm` | 相对照片有效深度范围的偏移 | 限制在 `[-0.35, 0.35]` |
| `confidence` | 局部校正可信度 `w` | `[0, 1]` |

90 帧存储量为：

`90 × 64 × 36 × 3 × 2 = 1,244,160 bytes`，约 `1.19 MiB`。

此外保存算法版本、网格尺寸、归一化参数、全局 LUT 和校验信息。首版优先保真；效果通过后可把参数量化为 8 bit，将局部场降至约 `0.59 MiB`。

## 5. 光流模型选择与接口

光流模块使用可替换接口：

```text
FlowEstimator.estimate_pairs(rgb_frames)
    -> forward_flow, backward_flow, model_confidence
```

参考实现优先接入 SEA-RAFT，因为其官方实现同时提供光流和不确定度，适合构建连续置信度；Torchvision RAFT-Small 作为环境兼容和可复现回退。具体手机端模型格式由目标推理后端决定，但算法层只依赖上述接口。

模型选择遵循以下规则：

1. 不确定度输出可用时，直接参与光流置信度。
2. 只有光流输出时，模型置信度取 1，依赖前后向一致性和图像边界检查。
3. 模型加载或推理失败时，V5 不生成局部场，完整回退 V4。
4. 手机端接受条件是在目标设备、目标推理后端上完成 90 帧双向流及参数生成的总耗时评测；1–2 秒是产品预算，不作为 Python 桌面原型的虚假结论。

参考资料：

- [SEA-RAFT 官方仓库](https://github.com/princeton-vl/SEA-RAFT)
- [RAFT 官方仓库](https://github.com/princeton-vl/RAFT)
- [Torchvision 光流示例与 RAFT-Small](https://docs.pytorch.org/vision/stable/auto_examples/others/plot_optical_flow.html)

## 6. 锚帧局部仿射场估计

### 6.1 基础深度

沿用 V4 的全局单调 LUT 和全局时域参数，生成基础深度：

`B_t = GlobalAlign(D_video_t)`

V5 只学习相对于 `B_t` 的有限局部增量，避免重新破坏已经稳定的整体尺度。

### 6.2 局部拟合

将锚帧划分为 `64 × 36` 个网格中心。每个中心使用重叠窗口内的有效像素拟合：

`P_anchor(x) ≈ a_g * B_anchor(x) + b_g`

采用置信度加权的稳健岭回归：

- 数据权重由照片有效性、视频深度有效性、局部 RGB/深度边缘和稳健残差共同决定。
- 对 `a_g=1`、`b_g=0` 增加正则先验。
- 邻近网格窗口重叠，避免块状独立拟合形成硬边界。
- 有效支持不足、条件数过高或残差过大时，降低该网格置信度，不强行填充。
- 参数经过约束裁剪，但置信度不因裁剪而提高。

锚帧置信度综合以下量：

`c_anchor = c_support * c_residual * c_condition * c_edge`

所有因子均为 `[0,1]` 的连续值，不生成二值区域 mask。

## 7. 双向光流置信度与遮挡处理

相邻帧的前后向一致性误差为：

`e_fb(x) = ||F_t→t+1(x) + warp(F_t+1→t, x + F_t→t+1(x))||`

流置信度定义为：

`c_flow = c_model * exp(-(e_fb / tau(x))^2) * c_in_bounds * c_photo`

其中：

- `tau(x) = 1.5 + 0.01 * ||F(x)||`，单位为光流工作分辨率像素。
- `c_in_bounds` 对越界采样取 0，边界附近平滑衰减。
- `c_photo` 由前后帧的亮度和梯度一致性构成，对曝光变化使用稳健截断。
- SEA-RAFT 不确定度转换为 `c_model`；无不确定度时取 1。

遮挡或新显露区域的 `c_flow` 接近 0，因此其参数不会从旧区域穿越过去。它们通过恒等先验回到 `a=1, b=0, w=0`，即使用 V4 结果。这一机制专门防止人物轮廓在墙面留下锚帧残差、黑缝或“7”形分层。

检测到镜头切换时，禁止跨切换传播；切换另一侧全部回退 V4。

## 8. 参数场传播与正则化

### 8.1 从锚帧双向传播

从锚帧分别向序列前后递推。对于每一对相邻帧：

1. 用对应方向光流反向采样上一帧的 `delta_scale`、`offset_norm` 和 `confidence`。
2. 将传播置信度乘以 `c_flow`。
3. 将无对应像素初始化为恒等参数。
4. 在当前帧网格上执行空间正则。
5. 对可信轨迹执行时间滤波。

传播的是缓慢变化的仿射参数，而不是高频照片残差。照片中的细节不会直接印到每一帧视频深度上。

### 8.2 边缘感知空间正则

在 `64 × 36` 网格上最小化：

`E(q) = Σ c_data ||q-q_warp||² + λ_s Σ w_ij ||q_i-q_j||² + λ_i Σ (1-c_data) ||q-q_identity||²`

其中 `q=(delta_scale, offset_norm)`，`q_identity=(0,0)`。邻接权重：

`w_ij = exp(-|ΔRGB|/σ_rgb - |ΔB|/σ_depth)`

首版使用固定 5 次 Jacobi 迭代，避免大规模线性求解。RGB 和当前视频深度共同抑制跨真实边缘扩散；在低纹理墙面内部则鼓励连续，避免网格分层。

### 8.3 轨迹时域滤波

在光流轨迹上对参数进行因果与反因果两遍指数滤波，权重由传播置信度控制：

`q_t = α_t * q_t^prop + (1-α_t) * warp(q_t-1)`

同时限制单帧参数增量：

- `|Δa| <= 0.03`
- `|Δb_norm| <= 0.02`

限制只作用于可靠轨迹；低置信度区域直接向恒等参数衰减，不把错误参数“稳定”下来。

## 9. 播放端联合上采样

播放端先把当前 `B_t` 缩小到 `64 × 36`，再将参数场上采样到深度输出分辨率。每个高分辨率像素只访问相邻 `2 × 2` 网格点，参数插值的引导权重为：

`r_k = w_bilinear * exp(-|B_t(x)-B_grid(k)|/σ_up_depth)`

使用归一化后的 `r_k` 分别插值 `delta_scale`、`offset_norm` 和 `confidence`，得到高分辨率的 `a`、`b`、`w`。置信度不参与 `r_k` 的归一化，避免低置信度节点被跳过后借用更远处的有效参数；它只在最终输出公式中控制局部校正强度。若四个引导权重之和过小，直接使用恒等参数。

该实现没有全分辨率卷积、迭代求解或神经网络。端侧参考目标是在约 `456 × 256` 深度分辨率上，C++/NEON 单帧新增耗时不超过 2 ms；最终结论以目标手机实测为准。

## 10. 防失效约束

1. **无硬区域边界**：不得使用固定矩形、连通域标签或二值人物区域直接切换参数。
2. **无照片残差传播**：光流只传播低频仿射参数和置信度。
3. **低置信度恒等回退**：任何失败都收敛到 V4，而不是传播最近的有效参数。
4. **参数幅度受限**：局部调整不能完全覆盖基础深度结构。
5. **真实深度边缘保护**：空间正则和播放端上采样均参考当前视频深度。
6. **场景切换隔离**：不跨切换传播。
7. **版本隔离**：通过 `algorithm_version="v5"` 启用；V4 路径和已有输出保持可复现。

## 11. 验证设计

### 11.1 自动化合成测试

1. **同值异校正**：构造两个视频深度值相同、照片目标不同的区域，证明 V5 局部误差显著低于全局 V4。
2. **运动前景与显露背景**：前景平移后，显露背景必须满足 `w≈0`，不得继承前景参数。
3. **运动边缘**：参数边界应跟随光流轨迹，背景平坦区不得产生静止轮廓。
4. **零置信度等价**：所有 `confidence=0` 时，V5 输出需逐像素等于 V4。
5. **越界与场景切换**：越界、切换两侧均不得传播参数。
6. **序列化一致性**：保存并重新读取参数场后的播放输出与准备阶段预览一致。

### 11.2 三个真实序列的硬门槛

每个视频只截取 3 秒、90 帧；保留当前 V4 作为基线。

#### 01 序列

- 第 0 帧墙右侧不得出现黑色竖缝，墙左侧不得出现红色竖向分层。
- 第 60 帧墙右侧不得出现“7”形轮廓或分层。
- 人物与墙边缘不得出现照片残差拖影。
- 墙面平坦区域的校正梯度 P99 不高于 V4：

  `P99(|∇(Y-B)|, where |∇B| < tau_flat)`

- 人物主体内部相对照片的局部 NMAE 相比 V4 至少降低 20%。

#### 02 序列

- 最后 15 帧头发和主体轮廓不得发生错误对齐。
- 主体内部时域误差不得比 V4 恶化超过 5%。
- 新显露背景不得保留人物局部参数。

#### 03 序列

- 不得产生新的单帧可见跳变。
- 全图最大帧间超额跳变不得比 V4 增加超过 `2e-4`。

### 11.3 主观输出

每个序列生成：

1. `raw video depth | V4 global | V5 local | photo anchor` 四栏深度对比视频。
2. `delta_scale | offset | confidence | flow consistency` 四栏诊断视频。
3. 01 第 0、60 帧和 02 尾帧的原分辨率 PNG。

所有深度视频使用同一个固定色标和值域，禁止逐帧归一化掩盖尺度或时域变化。

## 12. 性能预算

准备阶段 1–2 秒预算按以下比例管理：

| 模块 | 预算占比 |
| --- | --- |
| 双向小型光流 | 不超过 70% |
| 锚帧拟合、传播和正则 | 不超过 20% |
| 序列化与校验 | 不超过 10% |

原型必须输出每个模块的耗时和峰值内存。若目标设备上的双向逐帧光流超出预算，优化顺序为：

1. 降低光流输入分辨率但保持 `64 × 36` 参数场。
2. 只计算锚帧向两侧的必要相邻流并复用特征。
3. 使用 FP16、NPU/GPU 后端和帧批处理。
4. 在效果验收通过后评估关键帧光流加插值。

不通过减少置信度检查、改回单向流或传播照片残差来换取速度。

## 13. 实施边界与回滚

1. V5 作为独立算法版本实现，不覆盖 V4 配置和基线结果。
2. 光流权重允许缓存到项目模型目录；需记录来源、许可证、哈希和下载方式。
3. 所有新增模型和参数文件必须在 Git/LFS 策略中显式管理，避免普通 Git 提交超大二进制。
4. 每个实现阶段单独提交，出现回归可回退到最近一个通过门槛的提交。
5. 若 V5 未同时通过局部效果与时域稳定门槛，默认交付仍使用 V4，不以平均指标掩盖指定帧缺陷。

## 14. 设计结论

V5 的核心不是给全局 LUT 增加更多区域规则，而是建立“锚帧局部仿射估计—双向光流可信传播—遮挡恒等回退—低分辨率连续场—轻量播放”的完整数据链。它具备全局方法没有的局部表达能力，同时通过连续置信度和严格回退避免 V3/V4 早期版本的硬分层、轮廓拖影和主体破坏。
