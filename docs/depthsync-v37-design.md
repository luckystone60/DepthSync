# DepthSync V3.7 端侧算法设计说明

## 1. 目标与适用范围

Live Photo 由一段短视频和一张高质量照片组成，照片时刻与视频中间帧对齐。人像虚化场景中：

- 视频深度来自轻量流式模型，分辨率较低但具有较好的时域连续性；
- 照片深度来自较重模型，分辨率和细节更高，但只存在于拍照锚帧；
- 两套深度的尺度、偏移、非线性值域和局部结构不同，直接切换会产生深度及虚化跳变。

DepthSync 的目标是以照片深度为尺度与细节锚点，在尽量保留视频深度时序特性的前提下，生成与照片深度兼容的视频深度序列。V3.7 不在播放阶段运行额外神经网络，也不依赖稠密光流；端侧优先复用编码器或 ISP 已有的 block MV。

本文把算法分为两个阶段：

1. **拍摄后参数准备阶段**：读取整段视频深度、照片深度和 block MV，生成紧凑参数包；
2. **播放阶段**：逐帧读取视频深度和参数包，执行 LUT、低分辨率残差、边缘保护和静态照片引导。

## 2. 坐标、数值与符号

内部统一在 disparity 工作域处理，数值越大表示越近。若输入是 metric depth，则进入算法时转换为 `1 / max(depth, eps)`，输出时再反变换。

| 符号 | 含义 |
|---|---|
| `T` | 视频深度帧数，当前验证为 90 帧 |
| `k` | 照片锚帧索引，当前验证为 45 |
| `D_i` | 第 `i` 帧视频 disparity |
| `P` | 配准到视频深度坐标系的照片 disparity |
| `L_i` | 第 `i` 帧 8 节点单调 LUT |
| `B_i` | LUT 后基础深度，`B_i = L_i(D_i)` |
| `R_i` | 第 `i` 帧 16×9 动态残差网格 |
| `M` | 全片共享的 128×72 静态背景软掩码 |
| `S` | 全片共享的 128×72 照片目标层 |
| `E_i` | 第 `i` 帧边缘保护权重 |
| `Y_i` | DepthSync 输出 disparity |

## 3. 输入与中间数据规格

### 3.1 输入

| 数据 | 原型规格 | 推荐端侧规格 | 备注 |
|---|---:|---:|---|
| 视频深度序列 | `T×Hv×Wv`, FP32 | FP16/UINT16 | 当前样例约 456×256；要求帧间坐标一致 |
| 照片深度 | `Hp×Wp`, FP32 | FP16/UINT16 | 先配准并降采样到视频深度坐标系 |
| 锚帧索引 | INT32 | UINT8/UINT16 | Live Photo 当前固定为中间帧 |
| block MV | `T×GmH×GmW×2`, FP32 | INT16/Q 格式 | 位移按图像宽高归一化；验证适配器为 18×32 |
| MV 置信度 | `T×GmH×GmW`, FP32 | UINT8 | `[0,1]`；无置信度时可省略 |
| 人脸框 | 4×FP32 | 4×UINT16 | 归一化坐标，用于锚帧固定采样加权 |
| 照片到视频映射 | 可选稠密网格 | ISP/标定映射 | 没有映射时只做尺寸对齐 |

`Hv×Wv` 是算法主工作分辨率。所有尺寸表均以“高×宽”书写；OpenCV API 传参时使用“宽×高”。

### 3.2 参数准备阶段中间数据

| 数据 | 形状 | 类型 | 生命周期 | 用途 |
|---|---:|---:|---|---|
| `raw_i` | `Hv×Wv` | FP32 | 单次准备 | 工作域视频 disparity |
| `P` | `Hv×Wv` | FP32 | 单次准备 | 配准后的照片锚点 |
| `LUT_x/LUT_y` | `T×8` 各一份 | FP32 | 输出参数 | 单调分段映射 |
| `scale/offset/confidence` | `T` | FP32 | 调试/回退 | LUT 的受限逐帧 affine 修正 |
| `B_i` | `Hv×Wv` | FP32 | 准备阶段 | 构建时域统计与残差 |
| 动态残差 | `T×9×16` | FP32 | 输出参数 | 照片局部差异的低频补偿 |
| 静态掩码 | `72×128` | FP32 | 输出参数 | 仅在稳定背景使用照片目标 |
| 静态目标 | `72×128` | FP32 | 输出参数 | 照片深度的低成本空间引导 |
| guidance range | 标量 | FP32 | 输出参数 | 运行时边缘阈值归一化 |

原型为了便于验证会保存完整 `B_i`。端侧实现可采用两遍扫描：第一遍生成 LUT 和低分辨率时域统计，第二遍生成残差，避免额外长期持有一份完整 FP32 序列。

## 4. 参数准备阶段

### 4.1 照片配准与统一工作域

1. 将视频深度和照片深度转换到 disparity；
2. 使用标定/ISP 映射把照片深度对齐到视频深度坐标；
3. 照片缩放到 `Hv×Wv`，无效值保留为 NaN；
4. 计算照片的 10%–90% 鲁棒范围，后续残差裁剪、静态判断和边缘阈值均相对该范围设置。

照片与视频的几何配准误差不能由尺度同步消除。若两者视场、EIS crop 或镜头畸变不同，应优先修正映射。

### 4.2 锚帧全局 LUT

在锚帧 `k` 上进行确定性采样：

- 优先低梯度、有效深度区域，降低边界配准误差影响；
- 约 30% 样本来自人脸框，其余覆盖全图；
- 默认最多 2048 个样本。

先用鲁棒 affine 得到初始化和回退结果，再按视频深度值分箱，取每箱照片深度中位数并执行单调回归，生成 8 节点分段线性 LUT。单调约束避免深度顺序翻转。

锚帧基础深度为：

```text
B_k = L_k(D_k)
```

### 4.3 逐帧 LUT 时域传播

从锚帧向前、向后各扫描一次。block MV 用来在相邻基础深度之间建立稀疏对应，但不会逐帧重拟合 LUT 的非线性形状：

- 所有帧固定使用锚帧 LUT 的横轴及非线性形状；
- 每帧只估计一个小幅 scale 和 offset；
- scale 单步变化限制为 1%，offset 单步变化限制为照片鲁棒范围的 0.5%；
- 锚帧前后 1 帧锁定，随后在 6 帧范围内渐进解锁；
- 对应不足时沿用上一帧参数。

这样可避免输入分布轻微变化导致 LUT 节点跳动。

### 4.4 动态残差网格

锚帧残差为：

```text
R_k_full = P - B_k
```

残差按照片鲁棒范围的 35% 裁剪，轻微高斯平滑后压缩为 16×9。随后使用完整 block MV 向两侧传播，并按锚帧距离使用余弦权重衰减：

```text
w(d) = 0.5 × (1 + cos(pi × d / 30)),  0 <= d < 30
w(d) = 0,                              d >= 30
```

残差只表达低频空间偏差；人物轮廓等高频结构由视频深度和运行时边缘保护保留。V3.7 进一步把人物运动走廊对应的残差网格单元直接置零，避免残差 warp 和余弦衰减改变主体内部深度。锚帧主体的中位尺度偏差折算为一个裁剪到照片鲁棒范围 10% 内的固定 offset，并合入所有帧 LUT，因此不增加播放阶段算子或参数量。

### 4.5 静态背景检测

静态掩码在 128×72 网格上生成。每个网格单元综合以下条件：

1. 全片 block MV 幅值的 P90 小于阈值；
2. 去除每帧全局中位值后，时序深度 MAD 足够小；
3. 对时序深度执行半径 1 的时间中值，再计算全片最大值与最小值；单帧噪声被中值滤除，但连续两帧以上的片头/片尾人物占用仍会被捕获；
4. MV 中位置信度不低于 0.30；
5. 在扩展人脸区域内，照片 disparity 高于 P85 的近景像素作为人物硬屏障。

为消除平面区域的 block 网格孔洞，V3.7 对初始权重执行：

1. 5×5 闭运算填充孤立小孔；
2. `sigma=1.0` 的低通正则；
3. 重新乘以动态占用门控；
4. 向背景边界完成 2 个网格单元；
5. 重新施加扩展人脸区域的近景人物硬屏障。

V3.5 在所有深度边缘关闭静态照片层，导致 01 墙边约 15 像素宽的区域回退到尺度不同的视频基础深度，形成明显“分层”。V3.6 允许背景完成到边界，但全片共享掩码在人物运动轨迹上形成了轮廓形孔洞；当人物离开该位置时，孔洞边界会显现为拖影、竖线或网格。

V3.7 在 128×72 照片深度上用四邻域做轻量连通域划分，相邻 disparity 差不超过照片鲁棒范围 5% 时归入同一深度平面。先根据“时序占用变化 + block MV”得到人物运动走廊，再把与该走廊相交的完整深度平面从静态照片层中排除。这样静态/动态边界只落在真实照片深度断层上，不再沿人物轮廓或人工矩形切割平滑背景。该连通域计算仅在参数准备阶段运行，128×72 网格约检查 1.8 万条邻接边。

### 4.6 静态照片目标层

照片 disparity 缩放为 128×72 的全片共享目标层 `S`。静态掩码与目标层采用相同分辨率，避免粗掩码在墙边产生宽过渡带。

静态目标和静态掩码是全片共享数据，不需要逐帧重复存储。

## 5. 播放阶段

对每帧执行以下步骤：

1. 转换到 disparity 工作域；
2. 通过 8 节点 LUT 得到 `B_i`；
3. 对 `B_i` 做一次 7×7 最大值/最小值形态学梯度，得到局部深度范围；
4. 根据 guidance range 计算动态残差边缘保护权重 `E_i`；
5. 双线性放大 16×9 残差，并只在 `E_i` 允许的位置相加；
6. 双线性放大 128×72 静态掩码和 128×72 静态目标；
7. 使用离线阶段已经完成到背景边界的 `M` 进行静态照片融合；
8. 如输入是 metric depth，反变换回 depth。

公式为：

```text
B_i      = L_i(D_i)
D_dyn    = B_i + E_i × upsample(R_i)
W_static = upsample(M)
Y_i      = (1 - W_static) × D_dyn + W_static × upsample(S)
```

7×7 形态学梯度只保护粗动态残差，不再把静态照片层从墙边撤回。它应实现为可分离滑窗 max/min，而不是每像素执行 49 次比较。固定输出分辨率时，`M` 和 `S` 也可在播放前预展开；若内存更敏感，可使用逐行双线性插值。

| 项目 | 推荐格式 | 大小 |
|---|---:|---:|

## 7. 计算量与端侧落地建议

### 7.1 播放阶段

以约 456×256（约 11.7 万像素）为例，每帧主要操作为：

- 一次 8 节点分段线性 LUT；
- 一次 7×7 可分离 max/min；
- 三个低分辨率网格的双线性采样；
- 若干逐像素乘加和 clamp。

不包含神经网络、稠密光流或全分辨率 bilateral filter。Python/NumPy 原型约 3–4 ms/帧，仅用于相对比较；C++/NEON、Metal 或 Vulkan 的真实耗时必须在目标 SoC 上测量。CPU 实现优先建议：

- LUT 和 blend 使用 FP16/FP32 NEON；
- 形态学 max/min 使用水平、垂直两遍滑窗；
- 网格插值系数按输出尺寸预计算；
- 静态 `M/S` 只在 clip 切换时准备一次；
- 深度与输出缓冲原地复用，避免每帧分配。

### 7.2 参数准备阶段

该阶段不要求跟随预览帧率，可在拍摄完成后后台执行。端侧可行性取决于视频深度是否已经缓存、block MV 是否可直接获取，以及照片深度完成时间。建议两遍扫描并只长期保存：

- 逐帧 LUT/残差参数；
- 128×72 的时域统计；
- 当前帧和相邻帧基础深度。

当前 Python/NumPy 原型在三段 90 帧素材上的参数准备耗时约 14.6–16.2 ms/帧，即每段约 1.3–1.5 秒；其中包含 Python 循环和验证用 LK motion 读取开销，不代表端侧 C++ 实现。新增的深度平面连通域仅处理 128×72 网格，不增加播放阶段耗时。

若必须单遍流式处理，可先生成 LUT 和动态残差，待照片深度完成后补充静态层；人物短时占用检测需要 3 帧滑动中值以及每个 128×72 单元的运行最小值/最大值，不需要保存完整时序统计。

## 8. 回退策略

| 条件 | 回退行为 |
|---|---|
| 锚帧有效样本不足 | 使用鲁棒 affine；仍不足则单位映射 |
| 相邻帧对应不足 | 沿用上一帧 LUT 修正参数 |
| 无 block MV | LUT 使用同位置对应；关闭静态照片层或采用更严格阈值 |
| MV 置信度低 | 对应静态掩码置零，保留视频深度 |
| 深度边缘过强 | 动态残差权重置零；静态背景是否使用照片层由离线人物屏障和背景掩码决定 |
| 距锚帧超过 30 帧 | 动态残差置零，只保留 LUT；可靠静态区域仍可使用静态层 |
| 照片配准质量差 | 关闭残差与静态层，只使用全局 LUT/affine |

## 9. 当前验证结果与判定口径

三段本地素材均截取中间 3 秒、30 fps、90 帧，锚帧为第 45 帧。完整数值见 `reports/validation.md`。重点结论：

- 01 左墙中位值全片变化范围约 0.0002；
- 01 墙边锚帧误差 P95 由 V3.5 的约 0.0290 降至约 0.00053，连续回退带中位宽度由约 15 px 降至 3 px；
- 为避免用照片层“刷高”人物锚帧分数，V3.7 主动放弃被人物污染平面的照片复制，01 全局锚帧 NMAE 约为 0.0125；
- 主体时序 P95：01 从 V1 的约 0.00397 降至 0.00373，02 从约 0.00506 降至 0.00393，03 从约 0.00350 降至 0.00340；
- 三段素材的全局 motion-compensated 时序 P95 均低于对应 V1 affine 基线。

对比视频是 8-bit Turbo 色图并使用 MP4 编码。大面积平滑深度可能出现颜色量化伪轮廓；可视化量化前的固定亚 LSB ordered dither **不会修改保存的 FP32/FP16 深度**。V3.7 同时统计墙边专项指标和扩展人脸 ROI 内的主体时序 P95，用来分别约束静态平面分层与人物一致性。

## 10. 端侧风险清单

1. **照片/视频几何不一致**：尺度算法无法补偿 EIS、视场或畸变误差；
2. **block MV 语义不一致**：需确认方向、单位、坐标原点和置信度定义；
3. **深度约定不一致**：两路输入必须明确是 depth 还是 disparity、近远方向及无效值；
4. **移动细发与透明物体**：粗 MV 和低分辨率视频深度存在上限，边缘保护优先避免错误引导；
5. **量化与显示链路**：参数量化误差和 8-bit 可视化伪轮廓应分开评估；
6. **阈值泛化**：静态、边缘和残差阈值当前按照片鲁棒范围归一化，仍需更大规模真实数据回归；
7. **功耗峰值**：准备阶段可后台执行，播放阶段需在目标 CPU/GPU 上验证持续功耗和内存带宽。

## 11. 建议的端侧验收项

- 逐像素检查输出是否保持单调深度顺序；
- 锚帧、锚帧前后 1 帧及残差结束位置无跳变；
- 静态平面同时满足低时域范围和低空间伪分层；
- 人脸、头发、手臂、圆环等边缘无照片层泄漏；
- block MV 缺失和低置信度时能稳定回退；
- FP16/UINT16 参数包相对 FP32 原型误差在可接受范围；
- 目标 SoC 上记录准备耗时、播放耗时、峰值内存、带宽和温升。
