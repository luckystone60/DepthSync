# DepthSync V5 端侧算法说明

## 1. 目标与结论

Live Photo 的照片帧使用高质量单帧深度，视频使用轻量、时域稳定的视频深度。V5 的目标不是把照片深度残差直接复制到视频，而是：

1. 保留 V4 全局单调 LUT 作为稳定、无空间接缝的基础结果；
2. 只在照片锚帧估计低分辨率局部 `scale + offset` 增量；
3. 拍摄完成后的 1–2 秒准备阶段运行小型双向光流，沿可靠运动轨迹传输参数；
4. 播放阶段只读取逐帧小网格参数，不运行光流模型，也不读取照片深度；
5. 遮挡、越界、切镜或数据异常处令置信度为零，逐像素严格回退 V4。

当前验证表明局部尺度表达能力显著高于全局 V4，同时避免了早期“传播锚帧残差”造成的轮廓拖影。桌面 CPU 的 SEA-RAFT-S 尚不能达到 1–2 秒，端侧时延必须在目标 NPU/GPU 上实测。

本实现相对初始设计有一项经过真实序列验证的调整：不在传播后的每一帧重复空间正则化，也不对高可靠度 flow confidence 做逐帧累计相乘。两者在早期原型中分别造成参数场呼吸和校正幅度慢漂；最终版本改为“锚帧一次平滑 + 可信轨迹纯传输 + 不确定区域连续回退”。

## 2. 坐标与符号

内部统一使用 disparity，数值越大表示越近。若输入是 metric depth，应先转换为 `1 / max(depth, eps)`。

| 符号 | 含义 |
|---|---|
| `D_t` | 第 `t` 帧视频模型原始 disparity |
| `B_t` | V4 全局 LUT 输出，V5 的稳定基础深度 |
| `P_k` | 与视频第 `k` 帧对齐的照片深度 |
| `δa_t(g)` | 网格节点 `g` 的局部 scale 增量，实际 scale 为 `1 + δa` |
| `b_t(g)` | 以照片 P10–P90 范围归一化的局部 offset |
| `c_t(g)` | 局部场置信度，范围 `[0,1]` |
| `F` | 相邻帧双向光流及连续可靠度 |

## 3. 拍后准备阶段

### 3.1 生成稳定基础深度

先完整运行 V4：在锚帧拟合全局单调 LUT，整段固定 LUT 形状，仅允许受约束的逐帧全局微调，得到 `B_0 ... B_89`。V5 只学习相对于 `B_t` 的有限局部增量，不替换 V4。

### 3.2 双向小型光流

原型使用固定版本和权重的 SEA-RAFT-S，在 `144×256` RGB 上对 89 个相邻帧对执行正向、反向推理。可靠度由以下因素相乘：

- 模型不确定度；
- forward-backward consistency；
- 映射是否越界；
- 亮度与梯度一致性；
- 切镜检测结果。

光流仅是准备阶段中间量，不进入播放参数包。实际产品可替换为任意输出双向 flow 和连续 confidence 的小模型。

### 3.3 锚帧局部 affine 拟合

默认网格为 `Gh×Gw = 36×64`。每个节点使用约 2.5 个网格间距的重叠窗口，对 `B_k` 与降采样后的 `P_k` 做两轮 robust IRLS：

```text
min Σ w(x) · |a(g)·B_k(x) + b(g) - P_k(x)|²
    + λa·|a(g)-1|² + λb·|b(g)|²
```

约束为 `a∈[0.5,1.5]`、`b/photo_range∈[-0.35,0.35]`。支持像素不足的节点保持 identity。重叠窗口减小块边界，锚帧只执行一次置信度加权空间平滑。

### 3.4 参数纯传输

从锚帧分别向前、向后扫描。参数场通过对应方向光流 remap 到下一帧。可靠度 `r` 使用 `[0.05,0.25]` smoothstep 转为 visibility：

```text
u = clamp((r - 0.05) / (0.25 - 0.05), 0, 1)
visibility = u²·(3-2u)
c_t = warp(c_prev) · visibility
```

关键设计是：可信轨迹只传输已经拟合好的参数，不逐帧重新空间正则化，也不让 0.9 一类高可靠度在 90 帧中累计衰减。前者会造成参数场“呼吸”，后者会造成校正强度缓慢漂移。低可靠度和新显露区域则连续衰减到 identity。

## 4. 播放阶段

每帧先执行 V4，再读取该帧的三个 `36×64 FP16` 通道。对高分辨率像素 `x`，只访问周围 2×2 网格节点。空间双线性权重再乘以当前 V4 深度与节点参考深度的 bilateral 权重：

```text
w_i = bilinear_i · exp(-|B_t(x)-B_low_t(i)| / σd)
```

在有置信度支持的节点内归一化插值 `δa`、`b`，并单独得到上采样置信度 `c`。最终输出为：

```text
correction = δa(x)·B_t(x) + b(x)·photo_range
Y_t(x) = B_t(x) + c(x)·correction
```

深度引导的 2×2 插值用于阻止人物参数跨越深度边缘进入墙面，也阻止墙面参数在人物边缘形成竖缝或轮廓晕染。`c=0` 有专门的 identity 快路径，输出与 V4 逐位一致。

## 5. 中间数据规格

以下是当前三段验证素材的实际规格；产品规格可按输入分辨率等比例调整。

| 数据 | 原型规格 | 类型 | 生命周期/备注 |
|---|---:|---:|---|
| RGB 视频 | `90×256×455×3` | uint8 | 输入；光流前缩放到 `90×144×256×3` |
| 视频 disparity | `90×256×455` | FP32 | 输入；播放时可用 FP16/定点 |
| 照片 disparity | `1080×1920` | FP32 | 仅准备阶段，配准后降到视频深度尺寸 |
| 双向 flow | `2×89×144×256×2` | 原型缓存 FP16 | 仅准备阶段，可边推理边消费 |
| flow confidence | `2×89×144×256` | 原型缓存 FP16 | 仅准备阶段 |
| 局部 scale 增量 | `90×36×64` | FP16 | 播放参数包 |
| 局部 offset | `90×36×64` | FP16 | 播放参数包 |
| 局部 confidence | `90×36×64` | FP16 | 播放参数包 |
| `depth_low` | `90×36×64` | FP16 | Python 诊断缓存；产品可由当前 `B_t` 降采样，不计入参数包 |
| V4 LUT/逐帧参数 | 16 节点 + 标量 | FP16/FP32 | 播放参数包，体积远小于局部场 |

三个局部场通道总大小：`90×36×64×3×2 = 1,244,160 bytes`，约 1.19 MiB。播放只需当前帧约 13.5 KiB 的局部参数。效果确认后可评估 INT8/INT16 量化，将包大小进一步降低。

## 6. 计算量与端侧实现建议

### 准备阶段

- 主耗时是 178 次相邻帧方向推理；应合并正反向 batch，并优先部署到 NPU/GPU。
- 局部拟合、场 remap 和参数量化远小于光流模型开销，可用 CPU 多线程或 GPU 完成。
- 原型在桌面 CPU 上每段 90 帧约 35–41 秒，因此不能证明手机 1–2 秒目标。必须测量目标 SoC 的模型编译、峰值内存、热状态和端到端 wall time。
- 若内存紧张，可从锚帧向两侧流式计算：保留相邻两帧 RGB、当前 flow 和当前网格场，不保存整段 dense flow。

### 播放阶段

- 每像素成本为 V4 LUT、4 个邻点 gather、深度权重、归一化和一次 confidence blend。
- `exp` 可使用小 LUT、fast-exp 或 GPU texture/bilateral-grid kernel；CPU 建议 C++/NEON 向量化。
- Python/NumPy 原型的 V5 apply 实测约 17–18 ms/帧，仅用于功能评估，不代表端侧优化实现。
- 若播放预算严格，可将深度引导后的参数在准备阶段烘焙到更高网格，或把 bilateral 权重离散为少量深度 bin；需重新验证边缘接缝。

## 7. 回退与健壮性

| 条件 | 行为 |
|---|---|
| 光流模型/权重不可用 | 整段返回 V4 |
| flow shape、NaN 或序列长度异常 | 整段返回 V4，并记录原因 |
| 切镜 | 切镜边界 confidence 清零，不跨边界传播 |
| 遮挡、越界、FB 不一致 | 对应网格 confidence 连续降到零 |
| 局部窗口支持不足 | 节点 identity |
| 参数反序列化失败 | 禁用 V5，使用 V4 参数 |
| 任意像素 `c=0` | 该像素逐位等于 V4 |

不保存照片残差图，不传播人物 mask，也不在每帧重新拟合局部场。这三条分别避免轮廓拖影、分割依赖和时序呼吸。

## 8. 验证口径与结果

每个原视频只取与照片锚帧对齐的中间 3 秒，共 90 帧。深度对比视频固定使用照片深度 P02–P98 范围，不做逐帧自动拉伸。

最新结果见 [`../reports/validation-v5.md`](../reports/validation-v5.md)。关键结论：

- 01 主体锚帧 NMAE 从 0.02486 降到 0.01278，墙面平坦区修正梯度增量约 6%，低于 10% 门槛；
- 02 主体锚帧 NMAE 从 0.03781 降到 0.01216，尾段主体时序 P95 从 0.00403 降到 0.00399；
- 03 最大新增跳变 0.000205，低于 0.000240 门槛；
- 01/02/03 的自动门槛全部通过，但产品放行仍应包含真机全速播放人工检查。

本验证没有真实深度 GT，指标衡量的是与照片锚帧的相对一致性和视频时域连续性，不代表绝对深度精度。

- `field_diagnostics_v5.mp4`：scale、offset、field confidence、flow consistency；
- `v5_depth_color.mp4` / `v5_depth_gray.mp4`：V5 独立深度视频；
- `frame_XXX_comparison.png`：01 的 0/45/60 帧、02 尾段和 03 最坏跳变邻帧。

这些视频、模型权重、光流和深度缓存不提交 Git；代码、指标报告、模型来源校验和可编辑流程图提交版本库。
